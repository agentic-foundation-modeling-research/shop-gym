What we learned

Update, 2026-11-05. A later coverage check found sets that this survey missed. They make takeaways 1, 3, 4 and 5 out of date:

  • Dunnhumby, theLook and JD MSOM 2020 also join a catalog, user facts and history for the same users.
  • ShopSimulator, ShoppingBench and τ²-bench retail have variant options.
  • ShopCART and MeLi 2020 have readable search sessions.
  • ASOS GraphReturns, theLook and τ²-bench have returns.
  • UserArena also ties a persona to UI actions.

These sets are not in the tables below yet.

  • No dataset covers everything. Only KuaiSearch and H&M have a catalog, user facts and history for the same users, and neither fits mock_amazon (a Chinese video app shop, a fashion chain). This is why the complete step must record the provenance of each field it fills.
  • Readable product text comes from the Amazon family. AR23, ESCI, Amazon-M2, WebShop, Amazon-C4 and OPeRA all use Amazon products. The hashed clickstreams (RetailRocket, Diginetica, Coveo, Taobao, YOOCHOOSE) cannot fill a catalog. They are only statistical priors.
  • Variants and stock are almost absent. WebShop alone has a full option table, and RetailRocket alone has availability. Most sets give one price per product, so variants and stock must be inferred.
  • Event logs agree on view, add to cart and purchase. Search followed by result clicks is logged only in KuaiSearch, Diginetica, Coveo and the small OPeRA set. No log has returns. Time precision runs from ms to order only, so each event needs timestamp_precision.
  • OPeRA is the only set that ties a persona to UI actions: 51 users, 692 sessions and 28,904 actions. It is small, so it can check user simulation, not train it.
  • Licenses are the main release risk. Only 6 of 21 sets clearly allow commercial use. AR23, the planned first adapter, states no license on its card. Check each source before any release.

Field notes

  • Price: price is a string 'None' in the sample; one price per parent product
  • Variants: reviews carry asin (variant) and parent_asin; metadata is per parent_asin. No explicit option list; image 'variant' is image position, not an option

  • Brand: store field plus details JSON; no dedicated brand field
  • Event log: only reviews (one event per user-item review); no views, carts or purchases other than the verified_purchase flag
  • Description: list of strings, empty in the sample

Notes

  • Review and metadata are separate files; join review.parent_asin to meta.parent_asin. The README says to use parent ID, not asin, to find metadata.
  • Items counted from reviews, not from metadata files; some items lack metadata (README).
  • HF repo uses a loading script (trust_remote_code); the HF datasets-server viewer does not support it, so rows came from the README, not the server.
  • The README table in the HF card lists 'asin2category.json' and all_categories.txt (33 categories + Unknown).
  • Field-doc table in README says price is float, but the sample shows the string 'None'.
