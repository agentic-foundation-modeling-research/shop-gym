## Conventions

All paths under `templates/hydrogen/` are relative to
`packages/shop_arena/src/shop_gen/templates/hydrogen/` unless
prefixed.

The template package does not ship `vitest`. Behavioral verification
runs through:

1. **Type-check** — `pnpm --filter hydrogen tsc --noEmit`
   (already in `verifiers/tsc.py`).
2. **Build** — `pnpm --filter hydrogen build`
   (already in `verifiers/build.py`).
3. **Cassette replay** — re-run the `fixture_build_loop` cassette
   under `tests/shop_gen/cassettes/fixture_build_loop/` and assert
   the post-build `Header.tsx` imports the expected primitives.
4. **End-to-end smoke** — `final_eval/playwright_smoke.py` against
   `mock_hardware` confirms rendered nav still works.

Do not add a TS test runner to the template — every shop clones the
template, so test-runner deps would bloat every artifact.

Spec §N7. **Check:** `tsc --noEmit` clean; SSR snapshot-test (rendered to string) shows no `localStorage` access at render time. **Status:** Landed. `pnpm typecheck` (`react-router typegen && tsc --noEmit`) reports `No errors found` against the template tree; all five tests in `tests/shop_gen/test_template_smoke.py` pass (the shared typecheck subprocess check now exercises `AnnouncementBar.tsx`). Implementation notes: (1) SSR-safety is structural rather than test-asserted — every `localStorage` / `setInterval` / `clearInterval` reference (4 sites total) lives inside a `useEffect` callback or the `handleDismiss` click handler, never in the render body; the initial `useState` values (`dismissed: false`, `index: 0`) are deliberately picked to make the server-rendered HTML byte-identical to the first client render so React's hydration check stays clean, and any client-only deltas are adopted only after the effects fire. A grep over the file confirms zero `window.`/`localStorage` access outside `useEffect`/event-handler scopes — the template ships no TS test runner (per the plan's "Conventions" section) so we satisfy the task's SSR-snapshot intent via the structural invariant rather than adding a vitest dep that would ship to every cloned shop. (2) Both `localStorage` accesses are wrapped in `try/catch` — `getItem` and `setItem` can throw in privacy modes and sandboxed iframes, and a thrown read-side error would block the render path entirely; the catch blocks degrade silently to "not dismissed" / "persistence is best-effort" which matches the user-visible expectation (a non-functional dismiss is preferable to a crashed page header). (3) The rotation effect short-circuits when `messageCount <= 1` so we don't burn a `setInterval` on a no-op — single-message and empty-array cases skip the timer entirely. - [x] **T2.5** — `app/lib/use-nav-active.ts`: `useNavActive(): {isActive: (path: string) => boolean, isParentActive: (paths: readonly string[]) => boolean}`. Reads `useMatches()`; returns helpers a consumer can pass to className builders. Spec §"Bonus". **Check:** `tsc --noEmit` clean; `isParentActive(['/collections/x'])` true when current route is `/collections/x/sub`. **Status:** Landed. `pnpm typecheck` (`react-router typegen && tsc --noEmit`) reports `No errors found` against the template tree; all five tests in `tests/shop_gen/test_template_smoke.py` still pass (the shared typecheck subprocess check now exercises `use-nav-active.ts` end-to-end). Implementation notes: (1) the leaf-vs-ancestor split is deliberate — `useMatches()` returns root → leaf in order, so the `isActive` predicate compares only against the *last* entry's `pathname` (the page the user is actually on) while `isParentActive` accepts the descendant relationship. The naive alternative — `matches.some(m => m.pathname === path)` — would make every parent route's `isActive` return `true` simultaneously, since `useMatches()` includes every ancestor in the active hierarchy; that's exactly the contract collapse `isParentActive` exists to avoid. (2) Both predicates normalize a single trailing slash via a module-private `normalize(path)` so `/collections/men` and `/collections/men/` compare equal, matching `react-router`'s own NavLink semantics. The root path `/` is preserved as-is rather than collapsed to the empty string — the `startsWith(parent + '/')` rule used by the descendant check would otherwise treat *every* path as a descendant of root and light up every parent trigger on every page. (3) The descendant check is hoisted into a module-private `isAtOrUnder(current, parent)` helper that explicitly trailing-slash-guards the prefix comparison (`current.startsWith(parent + '/')`, not `current.startsWith(parent)`) so `/collectionsXother` does not match `/collections` as a descendant — the spec's behavioral assertion (`isParentActive(['/collections/x'])` true on `/collections/x/sub`, false elsewhere) survives this edge. Verified the rule with an isolated Node repro: leaf `/collections/x/sub` against parent `/collections/x` resolves to `true` (descendant); leaf `/collectionsXother` against parent `/collections` resolves to `false` (false-prefix rejected); leaf `/collections/y` against parents `['/collections/x']` resolves to `false` (sibling rejected); leaf `/collections/x` against parents `['/collections/x']` resolves to `true` (parent stays active when the user lands on it directly, not just on a descendant — most natural interpretation of the spec's intent, since the alternative would make a top-level nav entry de-highlight on its own landing page). (4) The returned object is wrapped in `useMemo` against the leaf pathname so passing the predicates to memoized `<NavMenu>` `linkClassName` / `triggerClassName` builders does not invalidate them on unrelated re-renders. (5) The empty-match-list case (e.g. an error boundary mounted above the router) returns predicates that unconditionally yield `false` rather than throwing — a user-visible "no nav highlights" state is strictly better than a runtime crash on the error path.
